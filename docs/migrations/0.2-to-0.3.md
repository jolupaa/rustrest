# Migrating from 0.2 to 0.3

RustRest 0.3.0 turns several experimental HTTP APIs into production-oriented contracts. The main
breaking changes are asynchronous request body extraction, structured HTTP errors, validated route
registration, fallible response streams and stricter HTTP semantics.

## Async Body Reads

Request bodies are streamed and consumed asynchronously. Body helpers now return `Result` from an
`async` call.

```rust
// 0.2
let bytes = req.bytes();

// 0.3
let bytes = req.bytes().await?;
```

```rust
// 0.2
let text = req.text();

// 0.3
let text = req.text().await?;
```

For large uploads, prefer the one-shot stream:

```rust
let mut stream = req.take_body_stream()?;
while let Some(chunk) = stream.next().await {
    let chunk = chunk?;
    // write/process chunk
}
```

See `examples/streaming_upload.rs` for a complete route that writes chunks to a temporary file and
removes partial output on stream errors.

## Extractors

Body-consuming extractors are asynchronous and use `Request::extract`.

```rust
// 0.2
let Json(input) = req.extract::<Json<CreateUser>>()?;

// 0.3
let Json(input) = req.extract::<Json<CreateUser>>().await?;
```

Parts-only extractors use `Request::extract_parts` and do not consume the body:

```rust
// 0.3
let Path(path) = req.extract_parts::<Path<UserPath>>().await?;
let Query(query) = req.extract_parts::<Query<ListQuery>>().await?;
let State(config) = req.extract_parts::<State<Config>>().await?;
```

Handlers can also receive typed extractor arguments directly. Parts extractors must come before one
optional body extractor:

```rust
async fn create_user(
    State(config): State<Config>,
    Path(team_id): Path<u64>,
    Json(input): Json<CreateUser>,
) -> Result<Response, HttpError> {
    Ok(Response::send(&format!("{}:{}:{}", config.name, team_id, input.name)).status(201))
}

app.post("/teams/:team_id/users", create_user)?;
```

`Json<T>` now validates `Content-Type` and accepts `application/json` and `application/*+json`.
Wrong media types return `415 unsupported_media_type`.

## Structured Errors

`HttpError` now carries a status, stable code, public message, optional source and headers. Error
responses use `application/problem+json` by default.

```rust
return Err(HttpError::bad_request("Nombre invalido"));
```

Handlers returning `Result<Response, E>` still work when `E: IntoHttpError`. Global error handlers
can format errors, while required protocol headers such as `Allow`, `Retry-After` and
`WWW-Authenticate` are preserved.

## Route Registration

Route registration is validated and returns `Result<RouteHandle, RouteError>`.

```rust
app.get("/users/:id", handler)?;
app.get("/health", health)?.name("health")?;
let url = app.url_for("health", [])?;
```

Invalid patterns, duplicate parameter names, duplicate routes and invalid host constraints are
reported at registration time.

## Body Limits

The application body limit still defaults to 64 KB, but it is enforced incrementally while reading
the stream. Routes can reduce the limit:

```rust
app.max_body_size(1024 * 1024);
app.post("/avatar", upload)?.body_limit(128 * 1024);
```

Known oversized `Content-Length` values are rejected before middleware or handlers read the body.
`Expect: 100-continue` is honored so middleware can reject unauthorized uploads before the client
sends the payload.

## Fallible Response Streams and Trailers

`Response::stream` accepts fallible streams. Errors propagate to the HTTP body instead of being
silently swallowed.

```rust
let chunks = stream::iter(vec![
    Ok::<_, std::io::Error>(Bytes::from_static(b"hello")),
    Err(std::io::Error::other("read failed")),
]);

Response::stream(chunks);
```

Responses can emit HTTP trailers:

```rust
let mut trailers = HeaderMap::new();
trailers.insert("x-checksum", HeaderValue::from_static("abc"));

Response::stream(chunks).with_trailers(trailers);
```

Prefer `try_status`, `try_header`, `try_append_header` and `try_with_trailers` when constructing
responses from untrusted values. The fluent wrappers record invalid values and render a structured
500 at the transport boundary.

## HTTP Semantics

Compression now honors weighted `Accept-Encoding` values, `identity;q=0`, wildcard coding and
`406 Not Acceptable`. It skips responses that must not be transformed, including `204`, `304`,
`206`, `image/*`, `Cache-Control: no-transform` and existing `Content-Encoding`.

Conditional requests evaluate preconditions in RFC order:

- `If-Match`
- `If-Unmodified-Since`
- `If-None-Match`
- `If-Modified-Since`
- `If-Range`

Static files and buffered ETag middleware return `412`, `304`, or ignore ranges as appropriate.

## Feature Flags

0.3.0 introduces named feature flags for future modularization: `compression`, `multipart`,
`static-files`, `sse`, `websocket`, `openapi`, `sessions`, `metrics` and `full`. Existing default
behavior is preserved in this release; dependency reduction is planned for later stabilization
work.
