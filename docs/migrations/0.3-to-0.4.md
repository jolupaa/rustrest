# Migrating from 0.3 to 0.4

RustRest 0.4 hardens the transport and makes resource limits, request
normalization, response framing, sessions, static files, and WebSockets safe by
default. Most route handlers continue to compile unchanged. The deliberate
breaking changes below remove APIs or behavior that could create security
ambiguities.

## Request Headers and Cookies

The public `Request::headers` and `Request::cookies` maps are now private.
Mutating one collapsed map could previously leave duplicate-aware and typed
extractors—or the parsed cookie view—seeing different values.

```rust
// 0.3
req.headers.insert("authorization".into(), value);
req.headers.remove("authorization");
req.cookies.insert("sid".into(), value);

// 0.4
req.set_header("authorization", &value)?;
req.remove_header("authorization");
req.set_cookie("sid", &value)?;
req.remove_cookie("sid");
```

Use `req.headers()` and `req.cookies()` for read-only map access,
`req.header(...)` for the collapsed value, and `req.headers_all(...)` when
duplicates matter. `set_header`, `append_header`, and `remove_header`
synchronize every header view. Cookie-header changes synchronize the parsed
cookie view as well.

## Server Safety Defaults

`App::new()` now applies finite production defaults, including a 30-second
request/body/handler deadline, HTTP/1 header-read deadline, HTTP/2 keepalive,
bounded connection admission, request-target/query/header limits, and a
graceful-shutdown deadline.

Review long-running handlers and raise a limit explicitly where necessary:

```rust
app.request_timeout(Duration::from_secs(120))
    .header_read_timeout(Duration::from_secs(10))
    .max_connections(2_000)
    .max_request_target_size(8 * 1024)
    .max_query_string_size(4 * 1024)
    .max_request_header_count(64)
    .max_request_header_bytes(16 * 1024);
```

Trusted deployments can use the named `disable_*` methods, but should enforce
equivalent limits at an edge proxy. Ordinary HTTP/1 connections intentionally
close after one response so every request receives the raw
`Transfer-Encoding`/`Content-Length` smuggling preflight. Use HTTP/2 when
upstream connection reuse is important.

Request authorities now use strict `host[:port]` syntax for both `Host` and
URI/HTTP/2 `:authority`. Userinfo, empty hosts, whitespace, and empty,
non-decimal, or greater-than-65535 ports are rejected with `400` even though
the underlying `http::Uri` parser accepts some of them. Hostname case,
equivalent IPv6 spellings, and omitted versus explicit scheme-default ports
are normalized when `Host` is compared with an absolute-form authority.

## Routing and CONNECT

Routing now prefers static segments over parameters, parameters over
wildcards, and an exact method over `all()`, independent of registration
order. Registered and incoming paths are strictly percent-decoded exactly once
and capped at 256 segments. Invalid UTF-8, malformed escapes, decoded controls,
and ambiguous duplicate patterns are rejected.

If registration now returns `RouteError`, fix the pattern rather than relying
on its former alias or ordering.

`RouteErrorKind` and `RouteMatchErrorKind` are now non-exhaustive. This lets
RustRest add more precise validation failures in later releases without
breaking consumers. Downstream matches must retain a fallback arm:

```rust
use rustrest::{RouteError, RouteErrorKind};

fn report_route_error(error: &RouteError) -> &'static str {
    match error.kind() {
        RouteErrorKind::DuplicateRoute => "route already registered",
        RouteErrorKind::InvalidHostPattern => "invalid host constraint",
        _ => "another route validation error",
    }
}
```

Apply the same pattern to `RouteMatchErrorKind`; do not use an exhaustive match
over only the variants known to 0.4.

`CONNECT` can no longer be registered as an ordinary route and receives `501`
even through `all()`. A CONNECT handler must own and drive a tunnel transport;
the normal response API cannot do that safely. Extension methods such as
`PURGE` remain supported through `route(Method, ...)`.

## Bodies, Extractors, and Multipart

The application body limit is a hard ceiling for buffered helpers, direct
collection, streams, route-specific limits, and multipart parsing. A
caller-supplied limit may reduce but not increase it.

`Option<E>` now suppresses only a genuinely missing extractor. Invalid JSON,
wrong content types, malformed fields, and oversized bodies return their
original rejection. Custom optional extractors must implement
`OptionalRejection`.

Multipart parsing now has independent part/count/header/value limits and
rejects folded or duplicate structural headers. Configure `MultipartLimits`
for legitimate large forms rather than disabling the application ceiling.

## Responses and HTTP Semantics

Network responses and `TestClient` now share strict finalization:

- conflicting or mismatched `Content-Length`, explicit `Transfer-Encoding`,
  invalid final informational statuses, and illegal trailer combinations
  become structured `500` responses;
- `204`, `205`, and `304` never carry a body; `HEAD` retains the equivalent
  representation length while dropping body and trailers;
- a `101` must come from the consuming WebSocket API and contain a valid
  handshake; a matching manually constructed accept digest is insufficient;
- compression and conditional middleware remove stale representation
  metadata and do not transform responses carrying trailers.

If an application intentionally emitted inconsistent framing, fix the
response builder. Use `try_status`, `try_header`, `try_append_header`, and
`try_with_trailers` when values are fallible.

Static files now open a capability-pinned root during route registration,
deny dotfiles by default, and treat metadata validators as weak ETags. Their
bounded producer has finite stalled-consumer and total-lifetime defaults so an
unconsumed HTTP/2 body cannot retain global file admission forever. A separate
first-poll lease covers bodies the transport never starts, while outbound
middleware time does not consume the active-producer deadlines. Byte ranges
apply only to `GET`; `HEAD` reports the full representation without reading
file contents.

## Sessions

Session secrets must contain at least 32 bytes. Configure a `Sessions` value
completely before cloning it or installing its middleware; configuration is
frozen while the shared store has more than one owner so clones cannot apply
different expiry or capacity rules to the same entries.

The store is bounded, sharded, and expiring. `Sessions::set` now returns
`Result<(), SessionDataError>`:

```rust
sessions.set(session_id, "usuario", "42")?;
```

Session creation is now lazy. Middleware still exposes a transient
`req.session_id()` so a handler can call `Sessions::set`, but an anonymous
read-only request is not persisted and receives no session cookie. The first
successful write admits the ID. When `max_sessions` live entries already
exist, a write for a new ID returns
`SessionDataErrorKind::SessionUnavailable`; RustRest does not evict a live
session to make room. Existing sessions continue to resume and renew, and
expired entries release capacity in bounded cleanup batches. Code that assumed
every request automatically created a cookie must perform an intentional
session write instead.

Session responses are marked private for caches, signed cookie lifetime tracks
the server-side sliding expiry, and ambiguous duplicate session cookies are
rejected rather than selected by ordering.

## WebSockets

Production defaults now bound origins, messages, frames, queues, buffers,
rooms, connection counts, per-IP admission, message rates, keepalive,
send/close operations, idle time, and connection lifetime. Review the
`WebSocketConfig` defaults and use explicit opt-outs only when another layer
provides the bound.

Configured subprotocols must now be unique valid HTTP tokens and matching is
case-sensitive as required by RFC 6455.

`Response::websocket(&Request)` is deprecated because it cannot own Hyper's
upgraded stream. Replace it with `App::websocket`, `Router::websocket`, or the
consuming request WebSocket API.

## Upgrade Checklist

1. Replace direct request header/cookie map mutation.
2. Configure the server and sessions before sharing them.
3. Review routes affected by strict normalization, specificity, or CONNECT.
4. Handle `Sessions::set` errors and extractor errors that `Option` no longer
   hides.
5. Verify long-running handlers and WebSockets against the finite defaults.
6. Run `cargo test --all-features` and
   `cargo clippy --all-targets --all-features -- -D warnings`.

The minimum supported Rust version remains 1.85.
